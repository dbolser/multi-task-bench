multi-task-bench

How well do models track many interleaved procedural tasks at once? Teacher-forced harness; every event is an independently graded “what is the next step for task T?” question. Code & docs.

Task length is a cliff; breadth is a slope

Chance of completing a task with zero errors — excluding the DONE event, so the stop-reflex failure below doesn't mask the tracking signal. Left: by the task's own length (raises), pooled over all runs. A clean run needs every raise right, so exposure compounds — and per-event accuracy itself also drifts down on longer tasks (more branch points, longer episodes).

By breadth (concurrent tasks), split by task length (solid = long tasks, dashed = short): scaling 30 → 100 short tasks barely moves the clean rate, while lengthening tasks at fixed breadth collapses it.

Accuracy by event type

The same models that ace step-following collapse on the final event — recognising that a task is finished (replying DONE) instead of incrementing to the next step number.
